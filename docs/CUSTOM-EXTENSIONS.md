## 更新の取り込み手順

作業中の変更をコミットしてから実施する。

```powershell
git fetch upstream
git switch main
git merge --ff-only upstream/main
git switch custom/quest-timeline-builds
git merge upstream/main
```

競合を修正し、ビルドと関連機能の確認後に独自版を保存する。共有済みブランチはrebaseやforce pushで書き換えない。GitHubのSync forkはmainに対して使う。機能追加のPRは自分のFork内で作成する。

```powershell
git push origin main
git push origin custom/quest-timeline-builds
```

## ユーザービルド保存の要件修正（2026-11-08）

対象は他プレイヤーの取得済みビルド。手入力メモ機能は要件を満たさず、置き換えが必要。

- 集計のプレイヤー名から、その集計時点のビルドを確認・保存する。
- ユーザー一覧 → 保存ビルド → そのビルドに紐づく集計一覧へ移動できる。
- プレイヤーはサーバーとCharacterIdで識別する。名前は表示用の当時の値を保存する。
- ビルドは取得時点のスナップショットとして保存し、最新情報で過去のビルドを上書きしない。
- 集計との紐づけにはEncounterIdを使用し、実際にその集計に記録があるユーザーのみ対象とする。同じ場所にいるだけでは参加と扱わない。
- 履歴表示中は当該履歴に保存されたプレイヤー情報を使用し、現在のライブ情報と混ぜない。
- 心相・アビリティ・イマジン・スキルタイムラインを保存対象とする。情報の出所と未取得状態を保持する。
- PlayerRosterEntryにはEquipmentData、RootBuffData、SeasonTalentBuffId、LastReplaceableSkillsなどがある。TalentNodeIdsは他プレイヤーには届かないため完全なアビリティ構成は保証できない。
- 観測されたバフや使用スキルから分かる情報と、全構成が確認できた情報を区別する。未取得を未装備・未習得と解釈しない。
- 紐づいた履歴が保存上限で削除された場合は、ビルドを残し、集計は削除済みと表示する。

現状: 要件と既存データ構造を確認。手入力ビルド画面からの置換・相互リンク・履歴時点の保存は未実装。

- 集計の当該エンティティだけを読み、現在のPT補完、特化・心相キャッシュ、スキル等級キャッシュを持ち込まない。
- イマジンは現時点では使用記録から確認できたもの。未使用の装備イマジンや改造段階を網羅する機能は未実装。心相は確認できた型・根バフを保存する。

## 技フィルター・ヘイト比較ゲージ（2026-11-08）

- タイムラインの「技フィルター」で観測した技を名前検索し、技単位で表示を切り替えられる。プロットとイベント表に共通で適用し、DPSグラフと記録データは変えない。
- 既定では集計時間に対して平均10秒に1回以上の技を非表示にする。同一エンティティ・同一技の時刻を数え、複数人の使用や同時刻の複数対象へのダメージで頻度を水増ししない。同じ技を使ういずれかのエンティティが基準以上なら、その技を既定非表示とする。ライブ中は経過時間に応じて判定が更新される。
- 手動指定を自動判定より優先する。「フィルターを保存」で表示・非表示の指定と有効状態をCombatExtensions.jsonへ保存。「既定に戻す」で手動指定を解除する。検索で隠れた候補の選択も保持する。技のキーに対象名やダメージ値を含めない。
- 敵名は各エンティティのAttrIdから表示言語の名前表で引き、リストとトラックで統一する。情報不足なら「未知の敵」とし、空欄にしない。
- 敵行動のアイコンはスキル表示と同じ別名解決を使う。配布データに絵がない技は汎用の技・予告マーカーで区別する。公式の絵がないものを別技の絵で埋めない。
- エンティティリストのヘイトは1人1本の横ゲージを縦に並べ、1位の値を100%として順位・名前・比率を表示する。既存の表示人数設定（最大5人）と狙われている相手の印を維持する。エンティティ情報ウィジェットの従来表示は維持する。

### ヘイト表示の小型化

エンティティ行を元の44px固定へ戻した。ヘイトは1人7px、ゲージ4px高・角丸2pxで、上位5人と現在の対象の計6段を42pxに収める。名前・順位・比率は小型表示、詳細はツールチップで確認できる。64項目の確認に成功し、6段が元の行内に収まることと丸い端の描画を確認した。

### ヘイト比率の分母修正

比率を1位基準から、受信した全プレイヤーの正のヘイト値の合計基準へ変更した。上位5人より下も分母に含み、表示人数を変更しても比率は変えない。整数合計のオーバーフローを避け、小数第1位で切り捨てて丸めによる表示合計の100%超過を防ぐ。ゼロ合計は0%。ゲージの小型・丸型表示は維持。

## r4：ヘイトPS・敵追跡・討伐履歴・読み込み表示

- ヘイトは敵ごとの一覧の差分を記録する。初回値・一覧から消えた後の再出現は基準値のみ、減少は増加量から除外する。エンティティリストの現在ヘイト割合と、正の増加量を集計するヘイトPSは別指標。
- ヘイトPSは観測した正の増加量を共通の集計秒数で割る。戦闘時計が未確定なら観測区間を使う。対象の敵・PTで絞り込み可能。技別割合は各プレイヤーの増加総量を分母とし、帰属不明も含めて一致させる。
- 推定技は前回観測から今回観測までに開始した技を照合する。更新間隔2秒以内、候補が1種類のときだけ割り当てる。継続効果やヘイト調整が混ざる可能性があるため、単一候補も推定と表示する。
- 新しいヘイト観測はExDataのProtoMember 28、討伐済みの敵は29に保存する。旧履歴のヘイト増加量を捏造しない。旧履歴の討伐済み敵は、その履歴の実体データにHP0で残っているものだけ表示する。
- エンティティリストの右クリックメニューに「ヘイトPSを開く」を追加。開いたときの敵UUIDに固定し、別の集計で対象がなければ未記録と表示する。全敵へ勝手に切り替えない。
- HP0の敵を「討伐済み（この集計）」へ分けて下部に残す。消失後も保存し、復活時は討伐済みから外す。過去集計の選択では保存された敵を表示し、ライブの敵情報を混ぜない。集計を切り替えるとその集計の履歴へ変える。
- 「遭遇した敵」で種類ごとの追跡設定と確認した技を保存する。キーはサーバー＋AttrId。過去集計から取り込み可能。個体UUIDは現集計のトラックと関連集計の参照に使う。関連集計IDはDB保存後に記録する（最大100件／種類）。
- 敵の技開始（AttrSkillIdの変化）を保存し、詠唱バーのある技は詠唱開始として表示する。既存の同時刻の詠唱記録とは重複させない。中断理由は推測しない。
- 集計の読み込みは「反映を予約」ではなく反映完了まで待つ。集計タブのコマンド完了時と再表示時に選択を照合し、通知未購読でも読み込み中の表示を解除する。失敗時・30秒タイムアウト時は要求を終了して再試行可能にする。元の症状の実ゲーム再現確認は別途必要。
- ウィジェット上部の「最前面＋クリック透過」ボタンは技術検討済み。既存機構を使えるが、全体透過では上部ボタンも押せないため、管理画面・既存ホットキーでの解除導線が必要。今回のr4には新しい透過ボタンは未追加。

## r7：命中・継続効果・回復によるヘイト照合

- 正のダメージと実際にHPが増えた回復について、プレイヤーUUID、対象UUID、到着時刻、DPS/HPSと同じ発生源キー（枝番込み）、バフ由来か、効果種別、発生量、分かる場合の技IDを記録する。弾・召喚からのダメージは既存の集計経路が解決したプレイヤーと発生源を使う。
- 空振り・無効化・純粋な過剰回復・プレイヤー以外からの攻撃は照合記録へ入れない。継続・効果ダメージも発動時刻ではなく実際の発生時刻で記録する。同じパケット内の同一発生源・対象・時刻の連続ヒットは発生量をまとめる。
- 照合記録はExDataのProtoMember 30へ保存する。旧履歴に命中・回復記録を捏造しない。既存のAddDamage/AddHealing公開シグネチャはオーバーロードとして維持する。
- ヘイトの前回観測より後、今回観測までの区間（2秒以内）で、同じプレイヤーの実発生を照合する。ダメージはその敵へのものだけ、回復は同じプレイヤーが味方へ実際に行った回復を候補にする。
- 発生源が1つで、別の技開始が競合しない区間を推定対象にする。同じ技の連続ヒットは1候補とするが、別の発生源・枝番は統合しない。公式のDPS/HPS対応表で同一行となるスキル・バフの別通知は同じ候補とする。対応表にない生IDは、スキルとバフで同じ番号でも区別する。別の敵の命中だけを根拠に、その敵のヘイトを付け替えない。
- 複数の原因が競合する、発生源不明の効果が混じる、観測間隔が2秒を超える場合は帰属不明を残す。ダメージ量に比例した推測の配分は行わず、正のヘイト差分を1回だけ推定先または帰属不明へ割り当てる。
- 実発生がない区間や旧履歴では、従来の開始通知による推定を維持する。技別行のツールチップに「命中」「継続・効果ダメージ」「回復」「開始通知のみ」を表示する。下部には各方式の照合件数と帰属不明割合を表示する。いずれもサーバー通知の技別ヘイト値ではなく推定である。
- 時刻の検索はプレイヤー単位の二分探索インデックスを使用し、各ヘイト増加で戦闘全体の全イベントを走査しない。
- 新旧の推定は、同じ集計・同じ戦闘時計の正の増加量を分母に比較する診断を追加した。旧履歴の互換性、実発生の保存とDB復元、別対象・別プレイヤー・時刻境界・複数原因・無効な攻撃・過剰回復を含む154項目の確認が成功。
